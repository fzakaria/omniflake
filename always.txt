# Flakes re-resolved on every run, one "owner/repo" per line.
# See tools/resolve.py.
#
# The default run re-resolves the --refresh-oldest rows resolved longest
# ago, which at 2,000 a run over ~16,000 rows brings each flake round about
# every eight days. That cadence is fine for a flake nobody is watching and
# wrong for one people follow daily: a week-old nixpkgs pin is visible.
#
# A repository listed here is re-resolved regardless of when it was last
# looked at, and does not spend the --refresh-oldest budget, so the cadence
# for everything else is unchanged. A repository whose HEAD did not move
# costs only the lookup, and pin.py is keyed by revision, so a line here
# adds real work only on the days the flake actually moved.
#
# Keep the list short. Every line is a GraphQL lookup on every run, and the
# rolling window already covers anything that is not moving fast.
#
# Each group below is a keep-sorted block; `nix fmt` sorts it and
# `nix flake check` fails on a group left unsorted.

# The five foundations. Their revision is substituted into every indexed
# flake, so these are the pins with the widest reach.
# keep-sorted start case=no
hercules-ci/flake-parts
nix-systems/default
NixOS/flake-compat
NixOS/nixpkgs
numtide/flake-utils
# keep-sorted end

# The flakes a NixOS or nix-darwin configuration follows closely enough
# that a stale pin gets noticed.
# keep-sorted start case=no
cachix/git-hooks.nix
Mic92/sops-nix
nix-community/disko
nix-community/home-manager
nix-community/nix-index-database
nix-darwin/nix-darwin
NixOS/nixos-hardware
numtide/treefmt-nix
ryantm/agenix
# keep-sorted end
